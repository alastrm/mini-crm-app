# Mini CRM API

REST API для учёта звонков организациям и назначения встреч менеджерам.
Позволяет вести список организаций, записывать результаты звонков и управлять расписанием.

Стек: Python 3.12+, FastAPI, Pydantic, SQLite (`sqlite3`), pytest.

## Запуск

Нужны Git и Python 3.12 или новее. Получите исходники:

```bash
git clone https://github.com/alastrm/mini-crm-app.git
cd mini-crm-app
```

### Windows PowerShell

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app
```

### Linux / macOS

Команда `python3` должна запускать Python 3.12 или новее.
В Debian/Ubuntu при отсутствии модуля `venv` установите его:

```bash
sudo apt update
sudo apt install python3-venv
```

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn app.main:app
```

Swagger UI: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs).
Остановить сервер: `Ctrl+C`. Для повторного запуска достаточно последней команды.

База `crm.sqlite3` создаётся в текущем каталоге при первом запуске.
Схема находится в `schema.sql`; перезапуск сохраняет данные.
Доступны тестовые менеджеры с ID `1` и `2`.

Путь к другой базе можно задать перед запуском; её родительский каталог должен существовать.

```powershell
$env:CRM_DB_PATH = "local.sqlite3"
```

```bash
export CRM_DB_PATH="local.sqlite3"
```

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| POST | `/companies` | Создать организацию |
| GET | `/companies` | Список организаций с фильтром и пагинацией |
| POST | `/calls` | Записать результат звонка |
| POST | `/meetings` | Назначить встречу |
| PATCH | `/meetings/{id}` | Перенести или отменить встречу |
| GET | `/managers/{id}/schedule?date=YYYY-MM-DD` | Расписание менеджера за день |

Форматы запросов и ответов доступны в Swagger UI.
Создание возвращает `201`, чтение и изменение — `200`.
Ошибки: `404` — запись не найдена, `409` — конфликт, `422` — неверные данные.

## Бизнес-правила

- Встреча длится ровно 60 минут и целиком помещается в рабочий день:
  пн–пт, 09:00–18:00 Asia/Almaty. Начало в 09:00 и 17:00 разрешено, в 17:30 — нет.
- Время принимается и возвращается в UTC ISO 8601 (`Z` или `+00:00`).
  Время без зоны и с другим смещением отклоняется.
- Активные встречи не могут пересекаться у одного менеджера или одной организации,
  даже если менеджеры разные. Соседние интервалы 10:00–11:00 и 11:00–12:00 разрешены.
- Перенос сохраняет `original_start_at` и `created_at`.
- Отмена освобождает слот; отменённую встречу нельзя перенести.
- Для результата звонка `meeting_set` нужна связанная активная встреча той же организации.
- Проверка слота и запись выполняются в одной транзакции SQLite с `BEGIN IMMEDIATE`.
  При блокировке дольше 5 секунд сервер возвращает `503`; запрос можно повторить.

## Тесты

Windows PowerShell:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Linux / macOS:

```bash
.venv/bin/python -m pytest -q
```

Проверяются валидация, расписание, границы рабочего дня, пересечения, переносы,
отмена, конкурентные запросы и откат изменений; каждый тест использует временную БД.

## Допущения

- Статус организации — результат последнего звонка: `no_answer`, `refused` или
  `meeting_set`; до первого звонка — `new`. Отказ не отменяет встречу автоматически.
- Несколько активных встреч одной организации допустимы, если их интервалы не пересекаются.
- История хранит первоначальный слот (`original_start_at`) и время создания записи
  (`created_at`); промежуточные переносы отдельно не записываются.
- Дата расписания означает местный календарный день Asia/Almaty.
  В расписании видны только активные встречи. Повторная отмена возвращает `200`.
- PATCH выполняет ровно одно действие: изменение `start_at` или `status=cancelled`.
- БИН хранится строкой из 12 цифр и уникален. Формат телефона не ограничен страной.
- SQLite выбран для локального запуска без отдельного сервера БД; одновременно
  допускается одна транзакция записи, поэтому параллельные изменения могут ждать.

## Ограничения

- Решение не проверено под высокой нагрузкой; проверка пересечений перебирает
  активные встречи затронутых менеджера и организации.
- Изменение существующей схемы не автоматизировано: `schema.sql` создаёт отсутствующие таблицы.

При разработке использовался Codex.
